# Upstream Superpowers v6.2.0 同步设计

## 背景

本仓库 fork 自 [obra/superpowers](https://github.com/obra/superpowers)，已重度魔改：
- 品牌命名：`superpowers` → `agent-harness`，`.superpowers/` → `.agent-harness/`
- 新增本地专属 skill：`auto-loop`、`harness-init`、`office-hours`、`plan-ceo-review`、`plan-eng-review`、`generate-issues`、`fix-issues-and-pr`、`post-deploy-monitoring`、`qa-testing`、`domain-modeling`、`retrospective`、`session-learnings`、`sprint-contract`、`trace-analysis`、`gate-driven-test-design`、`harness-design`
- 基础设施：`validate-handoff.sh`、phase-metrics、learnings、knowledge-base 索引约定
- SDD Fan-Out：`Blocking: none` 并行 dispatch + worktree 隔离 + merge-fix
- 支持平台：Claude Code / Codex / Pi（不含 Gemini CLI / OpenCode / Copilot CLI）

上游 v6.2.0 相比共同祖先 `dd23728` 有 263 commit / 163 文件（+21k/-3.7k），核心变更：
- SDD plan-scoped workspace 结构重构（`.superpowers/sdd/`）
- SDD resume-based fix loop + 5 轮熔断 + rationalization table
- 大规模 skill 压缩重写（19 个 refactor commit）
- `testing-anti-patterns.md` → `writing-good-tests.md` 重写
- Windows Git Bash SessionStart 分发、Codex GNU tar、find-polluter `./` 前缀等 bugfix
- Gemini CLI 恢复（**本项目不适用**）

## 目标

- 吸收上游精华（bugfix + skill 高质量新段落），提升本地 harness 质量
- 严守"取其精华去其糟粕"：拒绝与本地魔改冲突、用户已否决、或超出支持平台范围的变更
- 每处吸收留下 provenance（引用上游 commit sha），便于将来审计与追溯
- 保持当前分支 `feat/agent-sup-v6.2.0` 上完成，不新开分支

## 非目标

- 不做全量对齐 v6.2.0
- 不引入 Gemini CLI 相关代码/文档
- 不重构 SDD workspace 结构（`.agent-harness/sdd/` 保持现状；Fan-Out 实现独立演进）
- 不因上游 refactor 压缩而删除本地新增段落
- 不做 upstream Visual companion 相关设计（用户已明确移除）

## 架构与执行方式

### 分支与提交
- 分支：当前 `feat/agent-sup-v6.2.0`
- 提交策略：cherry-pick + 手动改路径/品牌 + 手动 review diff
  - `git cherry-pick -x -n <sha>` → sed `s|\.superpowers|.agent-harness|g` → 谨慎处理 `superpowers`（说明性文字与品牌均需人工确认）→ 手动确认 diff → `git commit`
  - commit message 保留 `Refs: <upstream-sha-7位>` trailer
- 每批次结束跑 `tests/plugin-infrastructure/run-all.sh` 冒烟；skill 改动结束跑相关 skill-behavior 测试

### 数据流

```
upstream v6.2.0 commits
    │
    ▼
按批次筛选 (P0/P1/P2/P3 分类) ─── 决策日志 (docs/.../sync/v6.2.0-log.md)
    │
    ├─── P0: 直接 cherry-pick + 路径适配
    ├─── P1: 逐 skill 手动合并（保留本地魔改 + 吸收上游精华段落）
    ├─── P2: 新增 writing-good-tests 目录
    └─── P3: 显式标记跳过（记入日志）
    │
    ▼
每批完成 → 冒烟测试 → 分批提交
    │
    ▼
最终更新 CLAUDE.md 记录同步版本号
```

### 组件划分

- **决策日志** `docs/agent-harness/sync/v6.2.0-log.md`：每个 upstream commit 的处置（采纳/改造/跳过）与理由；将来同步 v6.3.0+ 时可复用为「已处理」筛选依据
- **cherry-pick 批次脚本**（不入 git，一次性使用）：辅助批量筛选 upstream commit，输出待人工审阅清单
- **skill 精华合并**：手动逐段编辑本地 SKILL.md，不做机械 patch apply

### 错误处理

- cherry-pick 冲突：一律手动解决，不用 `git checkout --theirs/--ours` 自动策略
- sed 改路径可能误伤：所有替换后 `git diff --stat` 复查，重点看是否误改说明性文字里的 "superpowers"（如上游 README 中提到项目名的地方）
- 测试失败：单批次内立即回退，先修再进下一批

## 风险与规避

| 风险 | 规避 |
|---|---|
| sed 全局替换误伤说明性文字 | 每次替换后必做 `git diff --stat` + 人工复查 |
| 上游 skill 段落引用了本地不存在的其他 skill / 脚本 | 引入前验证依赖，缺失依赖直接改写引用或删除 |
