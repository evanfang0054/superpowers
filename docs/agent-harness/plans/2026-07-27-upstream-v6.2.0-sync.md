# Upstream Superpowers v6.2.0 Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use agent-harness:subagent-driven-development (recommended) or agent-harness:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不覆盖本地重度魔改的前提下，吸收 upstream v6.2.0 中经 spec 批准的 bugfix、Codex 能力、skill 段落和测试资料，并让 Contract 27 项 DoD 与 GDD assertions 全部可执行验证。

**Architecture:** 先固定 upstream tag、同步基线和决策日志，再按互不冲突的文件边界实施 P0、P0.5、P1、P2。P1 每个既有 skill 独立 task、独立行为评估、独立 commit；worktree policy 测试在 finishing skill 合并后落地，避免 read-after-write 失败。最终 verification task 以 SHA 集合而非 trailer 数量审计 provenance，并逐条执行 GDD 正向和负向 gate。

**Tech Stack:** Bash、Git、jq、Python 3、Node.js/tsx、Claude Code headless skill-behavior tests。

---

## Global Constraints

- 当前分支必须是 `feat/agent-sup-v6.2.0`；不创建新分支。
- 唯一 upstream tree ref 是本地 tag `v6.2.0`。禁止使用不存在的 `upstream/v6.2.0`。
- 任何实际吸收 upstream 内容的 commit 都必须含 `Refs: <SHA7>[, <SHA7>...]`；只 review/跳过的 SHA 只写 decision log，不进入 commit trailer。
- 纯本地日志、索引和评估记录 commit 不伪造 upstream `Refs`。
- 禁止 `git add -A`、`git add .`；每个 commit 只 stage task 的精确文件。
- 不使用 `sed -i`；文本改造使用 `python3` 或 Edit，保证 macOS/Linux 一致。
- P1 禁止机械覆盖整个 `SKILL.md`；只按 upstream section anchor 手动并入批准段落。
- P1 每个 skill 先记录 baseline，再运行对应 `tests/skill-behavior/<skill>/run-test.sh`；失败必须按测试输出修正，不能仅靠 grep 宣称完成。
- P1 行为测试的语义断言必须只读取 stream-json 中 assistant text/tool_use，不能匹配 Skill 工具返回的 `SKILL.md` 正文；每个 runner 用累计退出状态保留所有场景失败，不能让最后一个场景通过掩盖前序失败。
- P1 每个 skill 的目标测试先于 skill 改动提交到工作区并运行 RED；若新断言在旧 skill 上已通过，记录为 `already-covered` 并增强非 leading pressure，不得伪报 RED。改动后每个 runner 顺序运行两次，每次产生独立 headless session/log；两轮均 GREEN 才可提交。
- 每个实现 task 不修改共享 decision log；Task 18 根据各实现 commit 的 `Refs` trailer 串行回填状态和 commit SHA，避免 Fan-Out 文件冲突。
- 每个 task 的 diff 若超过 300 行，在该 task 内按“测试/实现”或独立 section seam 拆为两个 commit；用 `git diff --numstat` 对该 task 的全部 staged 文件计数，两个 commit 仅写各自实际吸收的 upstream SHA7。
- 每个实现 task 提交前运行 `tests/plugin-infrastructure/run-all.sh`。API 配额型 behavior test 仅运行对应 skill，不运行全量 suite。
- `superpowers` 品牌检查允许的唯一例外是明确的 upstream 仓库 URL `https://github.com/obra/superpowers`。
- Gemini 负向验收是“本次 diff 不新增 Gemini 恢复内容”，不是删除仓库既有合法平台说明。
